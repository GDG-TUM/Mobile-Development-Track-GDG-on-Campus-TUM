## How we work in this repo

We follow a simple but structured workflow based on industry practices.

### The flow
1. **Open an issue** - Describe what needs to be done
2. **Create a branch** - One feature or fix per branch
3. **Make changes** - Write clear code and documentation
4. **Open a pull request** - Ask for feedback
5. **Review** - Kind, specific feedback
6. **Merge** - After review approval
7. **Celebrate** - Share what was learned

### Branch naming
- `feature/add-firebase-auth`
- `fix/navigation-back-button`
- `docs/update-readme`

### Commit messages
Be clear and specific:
- ✅ `Add Firebase authentication flow`
- ❌ `Update stuff`

### Pull request template
When you open a PR, include:
- What you changed
- Why you changed it
- How to test it
- Any notes for reviewers
