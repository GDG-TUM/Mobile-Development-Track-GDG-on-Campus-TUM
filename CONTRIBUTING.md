# How to contribute

[← Back to Mobile Development Track home](../README.md)

## We value contributions

Improvements, fixes, new resources, and questions all make this track better. Whether you are a member, mentor, or lead, your ideas matter.

## Contribution ideas

- Fix a typo or unclear wording
- Add a resource or cheat sheet
- Share what you learned in a week
- Improve a code example
- Add your capstone project to the showcase
- Write a short summary of a tricky concept
- Suggest a project idea
- Report a bug or missing piece

## How to contribute

### 1. Fork or branch this repo

```bash
git clone git@github.com:GDG-TUM/Mobile-Development-Track-GDG-on-Campus-TUM.git
cd Mobile-Development-Track-GDG-on-Campus-TUM
git checkout -b fix/typo-in-readme
```

### 2. Make your change

Edit a file, add a note, update a link—whatever improves the track.

### 3. Commit with a clear message

```bash
git add .
git commit -m "docs: fix typo in week 1 README"
```

**Commit message format:**
- `docs:` for documentation changes
- `feat:` for new content or features
- `fix:` for bug fixes
- `chore:` for repo maintenance

### 4. Push and open a pull request

```bash
git push origin fix/typo-in-readme
```

Then open a PR on GitHub with a short description of what you changed and why.

### 5. Be patient and kind

Reviewers will offer feedback or merge your change. If they ask for changes, no problem—just update the same branch and push again.

## Good practices

- **Keep changes small.** One fix or idea per pull request is easier to review.
- **Write clear commit messages.** Future readers (including you) will thank you.
- **Test your changes.** If you edited code, make sure it works.
- **Be respectful.** Everyone here is learning.

## A note on AI tools

You are welcome to use AI tools (like GitHub Copilot, ChatGPT, or Claude) to help you write code and docs. We only ask that you:

1. **Understand what you submit.** Read it carefully before opening a PR.
2. **Say so in your PR description.** Example: "This PR was written with help from Copilot."
3. **Keep the spirit of learning.** Use tools to go faster, not to avoid thinking.

## Questions or stuck?

Ask in the track channel or open an issue. We are here to help.
